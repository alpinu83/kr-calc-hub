## 2. "너네가 접속해서 그런 거냐"에 대한 답

아니라고 판단합니다. 근거는 세 가지입니다.

1. **시점이 안 맞습니다.** 미국 유입이 가장 많았던 날은 11/22(26명, 16~22시)입니다. CEO Office에서 이 프로젝트 업무가 처음 만들어진 건 11/25 09:46입니다. 팀이 일을 시작하기 전부터 미국 접속이 몰렸습니다.

3. **Aside가 접속하면 한국으로 잡힙니다.** Aside는 대표님 PC의 브라우저로 사이트를 엽니다. 그래서 Aside 접속은 미국이 아니라 "한국·서울·Windows·Chrome"으로 기록됩니다. 대부분의 AI 팀원(Gemini·Groq·EXAONE 등)은 글만 생성하는 방식이라 사이트를 열지 않으므로 GA4에 안 잡힙니다.

오히려 반대 문제가 있습니다. **한국 21명 안에 대표님과 Aside의 접속이 섞여 있습니다.** 아래 4장 참고.

## 5. GA4에서 직접 확인하는 방법 (대표님·팀원용 가이드)

### 5-1. 도시로 데이터센터 걸러보기 (가장 빠름)
1. GA4 왼쪽 메뉴 **보고서 → 사용자 → 사용자 속성 → 인구통계 세부정보**
2. 표 위 측정기준을 **국가**로 두고, 표 머리의 **+** 를 눌러 2차 측정기준 **도시** 추가
3. Council Bluffs, Boardman, Ashburn, The Dalles, Moses Lake, Cheyenne, Frankfurt, Falkenstein 같은 도시가 위에 있고 참여 시간이 0~3초면 서버 접속입니다.

### 5-2. 유입 경로 보기
1. **보고서 → 획득 → 트래픽 획득**
2. 2차 측정기준에 **국가** 추가 → 국가별로 세션 소스/매체를 봅니다.
3. 해외가 전부 (direct)/(none)이면 봇 신호, organic(검색)·referral(다른 사이트 링크)이면서 참여가 있으면 사람 신호입니다.
4. 어떤 검색어로 왔는지는 GA4가 아니라 **서치콘솔 → 실적 → 검색어** 탭에서 봅니다(GA4에는 검색어가 거의 안 남습니다).

### 5-3. 기기·해상도·언어 보기
1. 인구통계 세부정보에서 2차 측정기준을 **화면 해상도**, **운영체제**, **언어**로 바꿔가며 확인
2. 800x600, 1024x1024, 2000x2000, 1600x20000 같은 해상도, 한국어 사이트인데 English 0초 방문은 자동 접속으로 봅니다.

### 5-4. 시간 패턴 보기
1. 2차 측정기준에 **날짜+시간(dateHour)** 추가
2. 한국 사용자는 낮·저녁에 몰리고, 봇은 새벽 포함 하루 종일 고르게 찍힙니다.

### 5-5. 보고할 때 숫자 뽑는 법
1. 보고서 상단 **필터 추가 → 국가 = South Korea** 로 고정한 값을 씁니다(현재 고정 지침).
2. 더 정확히 보려면 필터에 **참여 세션 수 > 0** 조건을 같이 겁니다.

### 5-6. 앞으로 데이터를 깨끗하게 쌓는 설정 (대표님 결정 필요)
- **내부 트래픽 정의**: 관리 → 데이터 스트림 → (세금계산기 스트림) → 태그 설정 구성 → 내부 트래픽 정의에 대표님 PC/사무실 IP를 넣습니다.
- **데이터 필터 켜기**: 관리 → 데이터 필터에 "Internal Traffic" 필터가 이미 있으나 상태가 **'테스트'** 라서 아무것도 빠지지 않고 있습니다. '활성'으로 바꾸면 그 시점 이후 내부 접속이 **영구히** 빠집니다(되돌려도 지난 데이터는 복구 안 됨).
- **맞춤 조건 필터**: 구글이 도시·브라우저·해상도 조합으로 봇을 영구 제외하는 필터 유형을 단계적으로 열고 있습니다. 이 속성에서 메뉴가 보이는지는 미확인입니다.
- 주의: 위 필터들은 앞으로 들어올 데이터에만 적용되고 지난 데이터는 바뀌지 않습니다. 이미 쌓인 142명은 보고서 필터로 걸러서 봐야 합니다.

## 6. '실제 방문'으로 인정할 체크리스트

아래 중 **4개 이상** 맞으면 실제 외부 방문으로 봅니다. 1~2개만 맞으면 봇 또는 미리보기로 봅니다.

- [ ] 국가가 대한민국이다 (한국어 세금 사이트이므로)
- [ ] 도시가 데이터센터 도시가 아니다 (Council Bluffs·Boardman·Ashburn·The Dalles·Frankfurt·Falkenstein 등 제외)
- [ ] 참여 시간이 10초 이상이거나 참여 세션으로 집계됐다
- [ ] 2페이지 이상 봤거나 스크롤 이벤트가 있다
- [ ] 유입 경로가 검색(organic) 또는 실제 커뮤니티·블로그 링크(referral)다
- [ ] 방문 페이지가 홈 하나가 아니라 특정 계산기·글 페이지다 (검색어와 내용이 맞음)
- [ ] 브라우저 언어가 한국어다
- [ ] 화면 해상도가 일반 PC·휴대폰 값이다 (800x600·정사각형·초대형 세로값 아님)
- [ ] 한국 시간 기준 사람이 활동하는 시간대다
- [ ] 내부 접속이 아니다 (대표님 PC, Aside 작업 시간, 링크프라이스·서치콘솔 관리 화면에서 넘어온 접속 제외)

## 7. 목표 지표와의 관계

- 프로젝트 목표 지표는 GA4가 아니라 **서치콘솔 28일 검색 클릭(현재 1 → 목표 300, 기한 2027-01-15)** 입니다. GA4에서 실제 검색으로 들어온 한국 사용자(다음 2·구글 1)는 이 지표와 같은 방향의 숫자입니다.
- 미국·유럽 봇은 목표 지표에 영향이 없고, 지우거나 막는다고 검색 클릭이 늘지도 않습니다. 이 문제에 더 시간을 쓰기보다 색인(12/3 재확인 예정)과 검색 노출 확보에 집중하는 게 맞습니다.
- 앞으로 진짜 사용 여부를 더 확실히 보려면 "계산하기 버튼 클릭" 같은 행동 이벤트가 있으면 좋습니다. 지금 GA4에는 기본 이벤트(page_view·scroll·user_engagement)만 있어 계산기를 실제로 썼는지는 알 수 없습니다. 필요하면 별도 작업으로 올리겠습니다(이번 요청 범위 밖이라 손대지 않음).
